# 컨설팅방 업로드 + 데모 배포 설계 (2026-07-20)

## 목적

Slack 컨설팅방(혼합 청중: 기술+비기술)에 프로젝트를 처음 소개하고 두 가지 피드백을 요청:
① 분석 방법론 검증(홀드아웃 튜닝·코호트 설계·카드 D 관측 재정의), ② 제품 방향성(다음 개발 우선순위).

## 전달 형식 (A안 — 사용자 승인)

- **본문 10~15줄**: 한 줄 소개 → "챗봇 아님, LLM은 통역만" 차별점 → 데모 링크+30초 사용법 → 명시적 피드백 요청 2개.
- **스레드 댓글 3개**: 💡 개발 여정·의사결정 / 🔧 스택·아키텍처 / 📊 검증 수치.
- 혼합 청중이 각자 필요한 깊이만 소비, 피드백이 스레드에 모임.

## 데모 배포 (Render Blueprint, 실데이터 — 사용자 결정 2026-07-20)

- **비공개 미러 리포**(코드 + git 제외 데이터 2개: `alumni.json`, `s_compass_courses.db`)에서 배포.
  공개 리포에는 데이터가 없어 배포 불가(의도된 제약). 미러는 로컬 `deploy` 브랜치에서 푸시.
- `render.yaml`: 백엔드(Python 웹서비스, uv) + 프론트(정적 사이트, `VITE_API_BASE` 주입).
- **안전장치**: ① 난수 접미어 서비스명(URL 추측 방지) ② `EXPOSE_DEBUG_ROUTES=0`으로
  `/courses` 비노출 ③ `ANTHROPIC_API_KEY` 미주입 — LLM 통역은 결정론 폴백, 외부 비용 0
  ④ 컨설팅 종료 후 서비스·미러 리포 삭제.
- 코드 변경 최소 2건: `config.py`에 `CORS_EXTRA_ORIGIN`/`EXPOSE_DEBUG_ROUTES`,
  `main.py`에서 CORS 배포 도메인 추가 + 디버그 라우터 조건부 등록. 로컬 기본값 무변경.

## 검증 기준

1. 로컬: 전체 테스트 통과, `EXPOSE_DEBUG_ROUTES=0`에서 `/courses` 404 · `/health` 200. ✅
2. 프론트 프로덕션 빌드 성공. ✅
3. 배포 후: 데모 URL에서 프로필 선택 → 분석 → 3카드 렌더 확인(무료 티어 첫 로딩 ~1분 안내 포함).

## 범위 밖

- Slack 실제 게시(사용자가 직접), Render 계정 연결(사용자 클릭 필요), 영상 녹화.
