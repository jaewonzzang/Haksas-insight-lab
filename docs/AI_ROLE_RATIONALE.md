# AI 역할 분담 — 설계 근거 (한 장 요약)

> **목적:** "추천도를 RAG/LLM에 맡겨라"식 지적에 대한 방어 논리. 이 프로젝트의 AI 사용 경계는 `CLAUDE.md`에 못박힌 결정이며, 아래는 그 *왜*를 1분 안에 설명하기 위한 요약이다.

## 한 줄 입장

**추천도(점수·순위·하드룰)는 결정론으로 계산하고, 생성형 AI는 강의계획서 해석·근거 설명에 쓴다.** LLM에게 추천도 산출 자체를 맡기지 않는다 — 의도적 결정이지 미검토가 아니다.

## 계층별 분업

| 계층 | 담당 | 왜 |
|---|---|---|
| 후보 필터 (개설학기·학과·복수전공·수강제한) | 결정론 | 하드룰은 예외 없이 지켜져야 함 |
| 선수과목 충족도 | 결정론 (AND/OR 트리) | 위반 시 추천 신뢰 붕괴 |
| **추천도 점수·줄세우기** | **결정론 + ML 가중** | **재현·평가 가능, 매번 같은 입력→같은 결과** |
| 수치 신호 (동학년 선배 수강이력, 출석 포함, 강의 방식 등) | 결정론 | 수치화 가능 → 가중 합산 |
| 강의계획서 산문 → 정형 특성 추출 | **생성형 AI** | 비정형 자연어 해석 = 생성형의 본령 |
| "왜 추천?" / 졸업생 패턴 한두 문장 | **생성형 AI (RAG grounding)** | 원문 근거로 환각 없는 설명 |

점수 결합 순서는 고정: `content(강의계획서 특성) + cohort(동학년·동진로) → hybrid → prereq 감산 → restriction 차단`.

## 왜 추천도를 LLM/RAG에 통째로 맡기지 않는가 (반박용)

1. **비결정성** — 같은 입력에 매번 다른 순위. 추천 시스템의 기본 계약 위반.
2. **평가·재현 불가** — "왜 이 점수?"를 감사할 수 없고, 본선 시연마다 결과가 흔들림(데모 리스크).
3. **하드룰 위반 위험** — 선수 미이수·수강 불가 과목을 LLM이 자신 있게 추천할 수 있음. 학사 데이터 기반이라는 신뢰가 무너짐.
4. **RAG의 본질적 한계** — RAG는 사실 검색·요약엔 강하지만 **일관된 수치 랭킹**엔 약함. 추천도 랭킹에 부적합.

## 생성형 AI는 어디에 쓰는가 (공모전 명분)

- **파싱·추출**: 강의계획서 PDF 산문을 구조화 특성으로 변환 — 명백한 생성형 NLP 작업.
- **근거 grounding (여기가 RAG의 정당한 자리)**: 추천 사유 한두 문장을 *해당 과목 강의계획서 원문에 근거해* 생성 → 환각 없는 "왜?".
- **요약 통역**: 졸업생 진로 패턴을 1단락으로.

→ 생성형 AI를 **추천도가 아니라 해석·설명 계층**에 배치. "RAG/생성형을 써라"는 요구를 점수가 아닌 이 계층에서 수용한다.

## RAG 적합 / 부적합 한 줄 정리

| 쓰임 | 적합? |
|---|---|
| 추천도 점수·순위 산출 | ❌ 비결정·평가불가·하드룰 위반 |
| 추천 사유를 원문 근거로 설명 | ✅ 환각 방어 |
| 강의계획서 비정형 해석 | ✅ (RAG가 아니라도 LLM 추출로) |

## 결론

추천의 **신뢰성(재현·평가·규칙준수)** 은 결정론이 책임지고, 생성형 AI는 **사람이 일일이 못 읽는 강의계획서를 해석하고 한두 문장으로 설명**한다. 이 분담이 곧 서강챗봇(RAG 자연어 대화)과의 차별점이다.
