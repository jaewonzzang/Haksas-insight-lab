# 차기 회의 안건 정리 (2026-07)

> 논의 필요 주제 4건 + 개발 현황 참고. 결정 사항은 회의 후 본 문서에 추가 기록.

## 1. 개발 지원금 30만원 사용처

- **확인 필요**: 개발 과정에서 실제 별도 비용(유료 API·서버·툴)이 필요한지
- **제안**: Claude + Higgsfield MCP 연동으로 발표 도입부 1분 내외 훅 영상 + PPT 제작에 일부 예산 사용 — 발표 초반 몰입 유도

**개발 측 실소요 (참고, 2026-07 기준):**
| 항목 | 소요 | 비고 |
|---|---|---|
| Anthropic API 크레딧 | **필요** — 최소 $5(약 7천원) | 추천 사유·진로 요약 통역(Haiku). 현재 크레딧 부족으로 라이브 검증 1건 보류 중. 분석 1회당 ~5원이라 $5로 시연 1,000회 이상 |
| 서버/배포 | **불필요 (무료)** | 프론트 데모 = Vercel 무료(24시간 접속). 백엔드 라이브가 필요하면 무료 컨테이너 티어로 충분 |
| 개발 툴 | 불필요 | |

→ 개발 실소요는 1만원 미만. **잔여 예산은 제안대로 영상·PPT에 쓰는 것이 합리적.**

## 2. 개발 디벨롭 (개발용 슬랙 활용)

- **여러 학생 케이스 시연**: 학교 ERP 실정에 맞춘 더미 데이터로 현재 샘플(재원 화면) 외 케이스 추가
  - *현황: 프로필 B~D 슬롯이 이미 구현돼 있음 — 학생 데이터(전공·학년·평점)와 이수과목 목록만 채우면 바로 동작*
- **SAINT 전환 플로우**: SAINT 로그인 → 버튼 클릭 → 우리 프로그램 진입 흐름 구현 + 화면 녹화로 데모 영상 활용
  - *현황: SAINT 화면 목업 + 전환 연출로 구현 가능 (실 연동 아님을 발표에서 명시할지 논의)*
- **UI**: 현재 수준으로 충분히 세련 — 큰 수정 불필요
- **멘토링 피드백 반영 (중요)**:
  - "실제 구현 방식에 대해 factchat 기반 프롬프팅을 넣으라" → 작동 방식 아이디어 고민 필요 (재원)
  - 챗봇 도입 시 "조건 선택 → 결과" 방식보다 유저–봇 자유 대화형을 심사위원이 선호할 가능성
  - *⚠️ 논의 필요: 현 설계 원칙은 "챗봇 아님 — 점수·판정은 결정론, LLM은 문장 통역만". 자유 대화형 챗봇은 이 원칙과 충돌하므로, 넣는다면 범위(예: 결과 대시보드 위에 "결과에 대해 질문하기" 레이어로 한정)와 원칙 수정 여부를 함께 결정해야 함*
- **핵심 포인트**: 가장 중요한 것은 **추천 점수 설계 알고리즘**
  - *현황: 6개 요인 가중 결합(코호트 25·콘텐츠 22·평점 18·선호 15·트랙 12·학년 8) + 선이수 감산 + 수강학년 필터. 현재 5개 요인 활성(강의평가 데이터만 부재) — 발표 5번 항목의 재료는 준비됨*
- **실행 제안**: 슬랙으로 코드 리뷰 + 프롬프팅/AI 요소 추가 연구

## 3. 발표 flow (브랜드 컨설팅, 대면 면담 3회)

**면담별 산출물 목표:**
| 면담 | 산출물 |
|---|---|
| 1차 | 컨셉 + 발표 플로우 점검 |
| 2차 | 발표 자료 초안 + 데모 영상 점검 |
| 3차 | 최종 발표 자료 + 리허설/팁 |

**발표 서사 (1차 면담 점검용 초안)** — 모토: "잘 아는 사람이 잘 만든다" (현업 실무자 + 실제 불편을 겪은 전공 재학생 팀)

1. Hooking 영상 (1분 미만) — 고민에 빠진 캐릭터(알로스)가 문제를 해결하는 Higgsfield 영상 (사람 등장 배제)
2. 발견한 문제 — 에타/선배 의존의 주관적 의사결정
3. 해결 방안 — 데이터 기반 객관적 추천
4. 실현 가능성 — 실제 학교 데이터 구조 소개
5. 추천 점수 알고리즘 방식
6. AI 활용 방식 (프롬프팅/챗봇 등)
7. 학교 적용 가능성 & 팀 역량 (현직자 + 재학생 조합)
8. 기대효과
